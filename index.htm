The NeuralEngine Architecture & Mathematics

From individual numbers to a trained neural network in C++20
Language: C++20 Standard Build System: CMake Architecture: Fully Connected Feedforward Target Problem: MNIST (784 → 10)

This document is a technical learning record for NeuralEngine: the mathematics behind the network, the derivations that connect the equations, the implementation ideas behind each operation, and the way the components work together to train a model on MNIST.

It is deliberately organised as a sequence. We begin with a single number and a single trainable parameter, introduce derivatives and gradient descent, generalise the calculations into vectors and matrices, then combine those operations into an entire neural network.

How to read this document

Three kinds of information appear throughout:

  • Mathematical result: the equation and the reasoning that establish it.
  • Implementation pattern: C++ illustrating how the mathematical operation can be implemented.
  • NeuralEngine source detail: behaviour visible in the code and project details discussed while building NeuralEngine.

The C++ snippets are not all copied from the project's source files. Where an exact implementation was available in the Studio code, that will be identified. Elsewhere, code is a reference implementation of the mathematics, not a claim that every line matches your library exactly.

Part I — What we actually built

1. What is NeuralEngine?

NeuralEngine is a neural-network engine written in C++20. Its purpose is not merely to call a machine-learning library, but to implement the fundamental operations needed to train and use a neural network.

The project brings together:

  • Tensor storage and indexing.
  • Dense, or fully connected, layers.
  • Activation functions, including ReLU.
  • Softmax and cross-entropy loss.
  • Gradients and backpropagation.
  • Stochastic gradient descent.
  • Weight initialisation.
  • MNIST image and label loading.
  • Model evaluation and prediction.
  • Saving and loading model checkpoints.
  • Tests of numerical behaviour and training-related functionality.
  • A Raylib-based Studio interface for working with models and datasets.

The central achievement is the connection between the mathematics and a working implementation. A model is not trained because its source code contains the word backpropagation. It is trained because the implementation calculates how the loss changes with respect to each parameter and then uses those gradients to adjust the parameters.

2. The experiment

The architecture used in the Studio configuration is:

\[ 784 \rightarrow 512 \rightarrow 256 \rightarrow 128 \rightarrow 64 \rightarrow 10 \]

This is a fully connected feed-forward network, not a convolutional neural network.

The input is a flattened \(28\times28\) image, and the ten outputs correspond to the ten digit classes, \(0\) through \(9\).

The reported training run used the MNIST dataset, with 60,000 training images and 10,000 test images. The Studio's displayed defaults included five epochs, a learning rate of \(0.01\), and He initialisation for the hidden layers. The Studio's network construction code selects Xavier initialisation for the final dense layer.

The project was reported to reach approximately 97.81% test accuracy after five epochs. (A single-epoch run with default parameters attained 94.61% test accuracy, 9,461 / 10,000 correct, mean test loss 0.178783).

Mathematical Result: What that result means
The model learned weights and biases that allowed it to classify most images in the test set correctly. It does not mean every digit is classified correctly. It does not prove the architecture is optimal. It does demonstrate that the implemented tensor operations, forward pass, loss calculation, backpropagation, optimisation, dataset pipeline, and evaluation process can work together as a functioning learning system.

Part II — The mathematical foundations

3. Start with a function and a parameter

Before considering layers of neurons, consider the simplest possible learning problem. Suppose we want a model to predict a value \(y\) from an input \(x\). We use the model:

\[ \hat y = wx \]

where:

  • \(x\) is the input.
  • \(w\) is a trainable weight.
  • \(\hat y\) is the prediction.
  • \(y\) is the desired answer.

Imagine that \(x=3\) and \(y=12\), and initially \(w=2\). The model predicts:

\[ \hat y = wx = 2(3) = 6. \]

The prediction is too small. How should we change \(w\)? We need a numerical measure of how wrong the model is.

4. Loss: measuring prediction error

A loss function maps a prediction and its target to a number representing the error for that example. A simple choice for regression is squared error:

\[ L = (\hat y - y)^2. \]

With our example:

\[ L = (6 - 12)^2 = (-6)^2 = 36. \]

A smaller loss is better, provided that the loss measures the behaviour we actually want.

For differentiation, it is common to include a factor of one-half:

\[ L = \frac{1}{2}(\hat y - y)^2. \]

The numerical loss becomes:

\[ L = \frac{1}{2}(6 - 12)^2 = \frac{1}{2}(36) = 18. \]

The factor \(\frac{1}{2}\) does not change the location of the minimum. Its main benefit is that the factor of \(2\) produced by differentiating a square cancels with the \(\frac{1}{2}\).

This particular loss is useful for learning the mechanics of gradients. NeuralEngine's MNIST classifier instead uses softmax cross-entropy, which is a more suitable loss for this multiclass classification task.

5. Derivatives tell us how the loss changes

A derivative measures how a function changes when its input changes by a small amount. For a differentiable function \(f(w)\), the derivative at \(w\) is:

\[ f'(w) = \lim_{h\to0}\frac{f(w+h) - f(w)}{h}. \]

The numerator is the change in the function value. The denominator is the change in the input. The limit asks what ratio emerges as the input change approaches zero.

For the model above:

\[ L(w) = \frac{1}{2}(wx - y)^2. \]

We want to know how the loss changes when we change \(w\). That is the derivative \(\frac{dL}{dw}\). Applying the chain rule:

\[ \frac{dL}{dw} = \frac{dL}{d\hat y}\frac{d\hat y}{dw}. \]

First, \(L = \frac{1}{2}(\hat y - y)^2\), so:

\[ \frac{dL}{d\hat y} = \hat y - y. \]

Next, \(\hat y = wx\), so, treating \(x\) as a constant:

\[ \frac{d\hat y}{dw} = x. \]

Combining the results gives:

Mathematical Result: Scalar Weight Gradient
\[ \boxed{\frac{dL}{dw} = (\hat y - y)x} \]

This is the gradient of the loss with respect to the weight. For our numerical example:

\[ \frac{dL}{dw} = (6 - 12)(3) = (-6)(3) = -18. \]

The gradient is negative. A small increase in \(w\) would decrease the loss locally. A small decrease in \(w\) would increase it locally.

The gradient does not directly tell us the perfect weight. It tells us a local direction of change and a measure of sensitivity.

6. Gradient descent: using the derivative to update the weight

Gradient descent updates a parameter in the opposite direction to its gradient:

Mathematical Result: Gradient Descent Parameter Update
\[ \boxed{w_{\text{new}} = w_{\text{old}} - \eta\frac{dL}{dw}} \]

where \(\eta\) is the learning rate. The learning rate controls the size of the update.

Take our values: \(w_{\text{old}} = 2\), \(\frac{dL}{dw} = -18\), and \(\eta = 0.1\). Then:

\[ w_{\text{new}} = 2 - 0.1(-18) = 2 + 1.8 = 3.8. \]

The weight increased, as expected from the negative gradient. The new prediction is:

\[ \hat y = 3.8(3) = 11.4. \]

The new squared-error loss is:

\[ L = \frac{1}{2}(11.4 - 12)^2 = \frac{1}{2}(-0.6)^2 = \frac{1}{2}(0.36) = 0.18. \]

The loss fell from \(18\) to \(0.18\). This example captures the essential mechanism behind training:

  1. Make a prediction.
  2. Measure the loss.
  3. Calculate the loss gradient.
  4. Update parameters in the opposite direction.
  5. Repeat.

A neural network performs the same conceptual sequence, but with many layers and often hundreds of thousands or millions of parameters.

7. A second worked example: calculate every parameter update

Consider a single linear neuron with two input values:

\[ x = \begin{bmatrix} 2 \\ -1 \end{bmatrix} \]

and two weights:

\[ w = \begin{bmatrix} 0.5 \\ -0.25 \end{bmatrix}. \]

Let the bias be \(b = 0.1\). The output is:

\[ \hat y = w_1 x_1 + w_2 x_2 + b. \]

Substitute the values:

\[ \hat y = 0.5(2) + (-0.25)(-1) + 0.1 = 1 + 0.25 + 0.1 = 1.35. \]

Let the target be \(y = 2\), and use the half-squared-error loss:

\[ L = \frac{1}{2}(\hat y - y)^2. \]

The error is:

\[ \hat y - y = 1.35 - 2 = -0.65. \]

Thus:

\[ L = \frac{1}{2}(-0.65)^2 = 0.21125. \]

Now differentiate with respect to each parameter. Because:

\[ \frac{\partial \hat y}{\partial w_1} = x_1, \qquad \frac{\partial \hat y}{\partial w_2} = x_2, \qquad \frac{\partial \hat y}{\partial b} = 1, \]

the gradients are:

\[ \frac{\partial L}{\partial w_1} = (\hat y - y)x_1 = (-0.65)(2) = -1.3, \] \[ \frac{\partial L}{\partial w_2} = (\hat y - y)x_2 = (-0.65)(-1) = 0.65, \] \[ \frac{\partial L}{\partial b} = \hat y - y = -0.65. \]

With learning rate \(\eta = 0.1\):

\[ w_1' = 0.5 - 0.1(-1.3) = 0.5 + 0.13 = 0.63, \] \[ w_2' = -0.25 - 0.1(0.65) = -0.25 - 0.065 = -0.315, \] \[ b' = 0.1 - 0.1(-0.65) = 0.1 + 0.065 = 0.165. \]

The model has updated all three parameters. Each one received a different gradient because each parameter influences the output differently.

This small example introduces several ideas that remain true in a dense neural-network layer:

  • Every weight has a gradient.
  • Every bias has a gradient.
  • The input influences the weight gradients.
  • The upstream error influences all these gradients.
  • All the updates use the same optimisation rule.

Part III — From scalars to vectors and matrices

8. Why use vectors?

A neural network processes many input features at once. For an MNIST image, the input consists of 784 pixel values. Writing 784 separate scalar equations would be cumbersome and would obscure the fact that the calculations follow the same pattern.

Instead, represent the input as a vector:

\[ \mathbf{x} = \begin{bmatrix} x_1 \\ x_2 \\ \vdots \\ x_n \end{bmatrix}, \qquad \mathbf{w} = \begin{bmatrix} w_1 \\ w_2 \\ \vdots \\ w_n \end{bmatrix}. \]

The weighted sum can be written using a dot product:

\[ z = \mathbf{w}^T\mathbf{x} + b = w_1 x_1 + w_2 x_2 + \cdots + w_n x_n + b. \]

The vector notation does not introduce a new mathematical operation. It expresses the same repeated multiplication and addition compactly. A vector of weights contains \(n\) independent trainable parameters, and each has its own partial derivative.

9. From one neuron to several neurons

Suppose a layer receives three inputs and produces two outputs:

\[ \mathbf{x} = \begin{bmatrix} x_1 \\ x_2 \\ x_3 \end{bmatrix}. \]

The two neurons each need three weights. Therefore, we can place their weights into a matrix:

\[ W = \begin{bmatrix} w_{11} & w_{12} & w_{13} \\ w_{21} & w_{22} & w_{23} \end{bmatrix}. \]

The first row contains all weights for the first output neuron. The second row contains all weights for the second output neuron. Let \(\mathbf{b} = \begin{bmatrix} b_1 \\ b_2 \end{bmatrix}\). The complete layer calculation becomes:

Mathematical Result: Dense Layer Affine Transformation
\[ \boxed{\mathbf{z} = W\mathbf{x} + \mathbf{b}} \]

In general, if a layer has \(n_{\text{in}}\) input features and \(n_{\text{out}}\) output neurons, then:

\[ W \in \mathbb{R}^{n_{\text{out}}\times n_{\text{in}}}, \qquad \mathbf{x} \in \mathbb{R}^{n_{\text{in}}\times 1}, \qquad \mathbf{b} \in \mathbb{R}^{n_{\text{out}}\times 1}, \qquad \mathbf{z} \in \mathbb{R}^{n_{\text{out}}\times 1}. \]

The inner dimensions must agree: \((2\times3)(3\times1) = (2\times1)\). A matrix with three columns cannot multiply a vector with four elements in this orientation. That is a dimension mismatch.

10. What matrix multiplication actually does

For matrices \(A\) and \(B\), the product \(C = AB\) is defined by:

\[ C_{ij} = \sum_k A_{ik}B_{kj}. \]

Each output element is a dot product between a row of \(A\) and a column of \(B\). For example:

\[ A = \begin{bmatrix} 1 & 2 \\ 3 & 4 \end{bmatrix}, \qquad B = \begin{bmatrix} 5 & 6 \\ 7 & 8 \end{bmatrix}. \]

Then:

\[ C_{11} = 1(5) + 2(7) = 19, \qquad C_{12} = 1(6) + 2(8) = 22, \] \[ C_{21} = 3(5) + 4(7) = 43, \qquad C_{22} = 3(6) + 4(8) = 50. \] \[ AB = \begin{bmatrix} 19 & 22 \\ 43 & 50 \end{bmatrix}. \]

Nothing more mysterious is happening inside a dense layer. The matrix multiplication computes the weighted sums for all its output neurons.

Part IV — Representing the mathematics in memory

11. A tensor is data plus shape

NeuralEngine has a Tensor abstraction. Conceptually, a tensor is a collection of numerical values together with information describing its shape:

  • Scalar: one value.
  • Vector of length four: shape \([4]\).
  • Matrix with two rows and three columns: shape \([2,3]\).
  • Three-dimensional tensor: shape \([2,3,4]\).

The rank is the number of dimensions in the shape. The shape tells the program how to interpret the contiguous memory.

12. Why contiguous storage matters

C++ does not have to store a matrix as a nested structure of separately allocated rows (such as std::vector<std::vector<float>>). A matrix can be represented by a single contiguous array.

For example, the matrix:

\[ A = \begin{bmatrix} 10 & 20 & 30 \\ 40 & 50 & 60 \end{bmatrix} \]

can be stored in row-major order as:

std::vector<float> values{ 10.0F, 20.0F, 30.0F, 40.0F, 50.0F, 60.0F }; // shape {2, 3}

For a two-dimensional matrix with \(R\) rows and \(C\) columns, the zero-based element \((i,j)\) has flat offset:

Mathematical Result: Row-Major 2D Offset
\[ \boxed{\operatorname{offset}(i,j) = iC + j} \]

For element \((1,2)\), \(\operatorname{offset} = 1(3) + 2 = 5\). values[5] is 60.0F.

13. General row-major indexing

For a tensor with shape \([d_0, d_1, \ldots, d_{r-1}]\), the row-major strides are:

\[ s_k = \prod_{j=k+1}^{r-1} d_j. \]

The flat offset for index tuple \((i_0, i_1, \ldots, i_{r-1})\) is:

\[ \operatorname{offset} = \sum_{k=0}^{r-1} i_k s_k. \]

For shape \([2, 3, 4]\), strides are \([12, 4, 1]\). Index \((1, 2, 3)\) has offset:

\[ 1(12) + 2(4) + 3(1) = 12 + 8 + 3 = 23. \]

14. An illustrative Tensor implementation

Implementation Pattern: Reference C++ Tensor Implementation
#include <cstddef>
#include <initializer_list>
#include <stdexcept>
#include <vector>

class ExampleTensor {
public:
    explicit ExampleTensor(std::vector<std::size_t> shape)
        : shape_(std::move(shape)),
          values_(element_count(shape_), 0.0F) {}

    float& at(std::initializer_list<std::size_t> indices) {
        return values_.at(offset(indices));
    }

    const float& at(std::initializer_list<std::size_t> indices) const {
        return values_.at(offset(indices));
    }

    const std::vector<std::size_t>& shape() const noexcept {
        return shape_;
    }

private:
    static std::size_t element_count(const std::vector<std::size_t>& shape) {
        std::size_t count = 1;
        for (const std::size_t dimension : shape) {
            count *= dimension;
        }
        return count;
    }

    std::size_t offset(std::initializer_list<std::size_t> indices) const {
        if (indices.size() != shape_.size()) {
            throw std::invalid_argument("Incorrect number of tensor indices");
        }
        std::size_t flat = 0;
        std::size_t dimension_index = 0;
        for (const std::size_t index : indices) {
            const std::size_t dimension = shape_[dimension_index++];
            if (index >= dimension) {
                throw std::out_of_range("Tensor index out of range");
            }
            flat = flat * dimension + index;
        }
        return flat;
    }

    std::vector<std::size_t> shape_;
    std::vector<float> values_;
};

15. Why std::span came up

A std::span<T> describes a contiguous range of existing objects without owning the memory: 

std::span<float> data();
std::span<const float> data() const;

The mutable form allows changes to the tensor's elements; the const form prevents mutation. Crucially, a span does not extend the lifetime of the underlying data.

16. Reference matrix multiplication in C++

Implementation Pattern: Reference Row-Major Matmul
std::vector<float> matmul(
    const std::vector<float>& a,
    const std::vector<float>& b,
    std::size_t m, std::size_t k, std::size_t n
) {
    if (a.size() != m * k || b.size() != k * n) {
        throw std::invalid_argument("Invalid matrix storage");
    }
    std::vector<float> c(m * n, 0.0F);
    for (std::size_t i = 0; i < m; ++i) {
        for (std::size_t p = 0; p < k; ++p) {
            const float a_ip = a[i * k + p];
            for (std::size_t j = 0; j < n; ++j) {
                c[i * n + j] += a_ip * b[p * n + j];
            }
        }
    }
    return c;
}

Part V — The dense layer

17. The affine transformation

A dense layer applies a learned linear transformation and adds a bias:

\[ \boxed{\mathbf{z} = W\mathbf{a} + \mathbf{b}} \]

Consider a 2-input, 2-output layer:

\[ \mathbf{a} = \begin{bmatrix} 2 \\ 1 \end{bmatrix}, \qquad W = \begin{bmatrix} 0.5 & -0.25 \\ -1 & 0.75 \end{bmatrix}, \qquad \mathbf{b} = \begin{bmatrix} 0.1 \\ 0.2 \end{bmatrix}. \] \[ z_1 = 0.5(2) + (-0.25)(1) + 0.1 = 1 - 0.25 + 0.1 = 0.85. \] \[ z_2 = (-1)(2) + 0.75(1) + 0.2 = -2 + 0.75 + 0.2 = -1.05. \] \[ \mathbf{z} = \begin{bmatrix} 0.85 \\ -1.05 \end{bmatrix}. \]

18. Why do we need a bias?

Without the bias, a neuron calculates \(z = \mathbf{w}^T\mathbf{x}\). The hyperplane \(z=0\) passes through the origin. Adding \(b\) allows the decision boundary to shift freely.

19. The number of parameters in a dense layer

Mathematical Result: Dense Layer Parameter Count
\[ \boxed{N_{\text{parameters}} = n_{\text{in}}n_{\text{out}} + n_{\text{out}} = (n_{\text{in}} + 1)n_{\text{out}}} \]

For layer 1 (\(784 \rightarrow 512\)): \(784(512) + 512 = 401,920\) parameters.

20. A dense layer in C++

Implementation Pattern: Dense Layer Forward Pass Loop
for (std::size_t o = 0; o < output_size; ++o) {
    float value = bias[o];
    for (std::size_t i = 0; i < input_size; ++i) {
        value += weights[o * input_size + i] * input[i];
    }
    output[o] = value;
}

Part VI — Why a neural network needs activations

21. Stacking linear layers is still linear

Suppose we stack two affine layers with no activation:

\[ \mathbf{z}_1 = W_1\mathbf{x} + \mathbf{b}_1, \qquad \mathbf{z}_2 = W_2\mathbf{z}_1 + \mathbf{b}_2. \] \[ \mathbf{z}_2 = W_2(W_1\mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2 = (W_2W_1)\mathbf{x} + (W_2\mathbf{b}_1 + \mathbf{b}_2) = W'\mathbf{x} + \mathbf{b}'. \]

This collapses into a single affine transformation. Depth alone does not provide representational power without nonlinearity. Activation functions provide the nonlinearity.

22. ReLU

Mathematical Result: Rectified Linear Unit
\[ \boxed{\operatorname{ReLU}(z) = \max(0, z)} \]

Applied to \(\begin{bmatrix} 0.85 \\ -1.05 \end{bmatrix}\), it yields \(\begin{bmatrix} 0.85 \\ 0 \end{bmatrix}\).

23. The derivative of ReLU

\[ \operatorname{ReLU}'(z) = \begin{cases} 1, & z > 0, \\ 0, & z < 0. \end{cases} \]

At \(z=0\), implementations conventionally choose subgradient 0. The incoming gradient \(g\) is gated elementwise:

\[ g_{\text{input}} = g_{\text{output}} \operatorname{ReLU}'(z). \]

24. Other activation functions

  • Sigmoid: \(\sigma(z) = \frac{1}{1 + e^{-z}}\), derivative \(\sigma'(z) = \sigma(z)(1 - \sigma(z))\). Saturates at both tails.
  • Hyperbolic tangent: \(\tanh(z) = \frac{e^z - e^{-z}}{e^z + e^{-z}}\), derivative \(\frac{d}{dz}\tanh(z) = 1 - \tanh^2(z)\).

Part VII — The complete forward pass

25. The layer-by-layer equations

Let \(a^{(0)} = x\). For hidden layers \(l=1\dots4\):

\[ z^{(l)} = W^{(l)}a^{(l-1)} + b^{(l)}, \qquad a^{(l)} = \operatorname{ReLU}(z^{(l)}). \]

For the final layer (\(L=5\)):

\[ z^{(L)} = W^{(L)}a^{(L-1)} + b^{(L)}. \]

The final dense layer produces unnormalized real-valued logits (no ReLU).

Part VIII — Softmax: converting class scores to probabilities

28. Why logits need to be converted

Logits can be negative, greater than one, or zero. Softmax converts them into a valid probability distribution:

Mathematical Result: Softmax Mapping
\[ \boxed{p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}} \]

29. Calculate a softmax example by hand

For logits \([2, 1, 0]\):

\[ e^2 \approx 7.3891, \qquad e^1 \approx 2.7183, \qquad e^0 = 1.0. \] \[ \sum = 7.3891 + 2.7183 + 1.0 = 11.1074. \] \[ p_0 = \frac{7.3891}{11.1074} \approx 0.6652, \qquad p_1 = \frac{2.7183}{11.1074} \approx 0.2447, \qquad p_2 = \frac{1.0}{11.1074} \approx 0.0900. \]

30. Why softmax needs numerical stability

In 32-bit floating point, \(e^{1000}\) overflows into inf. By factoring out \(c = m = \max_j z_j\):

\[ \frac{e^{z_i - m}}{\sum_j e^{z_j - m}} = \frac{e^{-m}e^{z_i}}{e^{-m}\sum_j e^{z_j}} = \frac{e^{z_i}}{\sum_j e^{z_j}}. \]
Mathematical Result: Stable Softmax
\[ \boxed{p_i = \frac{e^{z_i - m}}{\sum_j e^{z_j - m}}, \qquad m = \max_j z_j} \]

For logits \([1000, 1001, 999]\), subtracting 1001 yields \([-1, 0, -2]\), which evaluates safely without overflow.

31. Reference C++ implementation of stable softmax

Implementation Pattern: Stable Softmax Function
std::vector<float> softmax(const std::vector<float>& logits) {
    if (logits.empty()) throw std::invalid_argument("Empty logits");
    const float maximum = *std::max_element(logits.begin(), logits.end());
    std::vector<float> probabilities(logits.size());
    for (std::size_t i = 0; i < logits.size(); ++i) {
        probabilities[i] = std::exp(logits[i] - maximum);
    }
    const float sum = std::accumulate(probabilities.begin(), probabilities.end(), 0.0F);
    for (float& p : probabilities) {
        p /= sum;
    }
    return probabilities;
}

Part IX — Entropy, cross-entropy and classification loss

32. Entropy is not the same thing as cross-entropy

  • Entropy: Measures intrinsic uncertainty of a distribution: \[ H(p) = -\sum_i p_i \log p_i \]
  • Cross-entropy: Penalises divergence between target \(y\) and prediction \(p\): \[ \boxed{H(y, p) = -\sum_i y_i \log p_i} \]

33. Why the target being correct is not enough

If target is 7: predicting class 7 with \(p_7 = 0.9\) gives loss \(-\ln(0.9) \approx 0.1054\). Predicting class 7 with \(p_7 = 0.2\) gives \(-\ln(0.2) \approx 1.6094\). Both predict the correct class, but cross-entropy penalises low confidence.

34. The categorical target and one-hot notation

For one-hot vector where \(y_k = 1\) and all other elements are 0:

\[ L = -\sum_{i=0}^9 y_i \ln p_i = -\ln p_k. \]

35. Cross-entropy from softmax logits

\[ L = -\ln\left(\frac{e^{z_y}}{\sum_j e^{z_j}}\right) = -\left(z_y - \ln\sum_j e^{z_j}\right) = \ln\left(\sum_j e^{z_j}\right) - z_y. \]

With numerical shift \(m = \max_j z_j\):

Mathematical Result: Numerically Stable Log-Sum-Exp Cross Entropy
\[ \boxed{L = m + \ln\left(\sum_j e^{z_j - m}\right) - z_y} \]

36. Calculate the cross-entropy example completely

For logits \([2, 1, 0]\) with target class 0: \(p_0 \approx 0.6652\), so \(L = -\ln(0.6652) \approx 0.4076\). If target were class 2: \(p_2 \approx 0.0900\), so \(L = -\ln(0.0900) \approx 2.4076\).

Part X — The most important derivative: softmax plus cross-entropy

37. Why this derivative matters

We need the gradient of the loss with respect to every output logit:

Mathematical Result: The Softmax Cross-Entropy Logits Derivative
\[ \boxed{\frac{\partial L}{\partial z_k} = p_k - y_k} \]

38. Derive the result from the softmax Jacobian

Given \(p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}\), differentiate with respect to \(z_k\):

  • When \(i = k\): \(\frac{\partial p_k}{\partial z_k} = p_k(1 - p_k)\).
  • When \(i \ne k\): \(\frac{\partial p_i}{\partial z_k} = -p_i p_k\).

Using Kronecker delta \(\delta_{ik}\):

\[ \frac{\partial p_i}{\partial z_k} = p_i(\delta_{ik} - p_k). \]

Applying chain rule to loss \(L = -\sum_i y_i \ln p_i\):

\[ \frac{\partial L}{\partial z_k} = -\sum_i \frac{y_i}{p_i}\frac{\partial p_i}{\partial z_k} = -\sum_i \frac{y_i}{p_i} p_i(\delta_{ik} - p_k) = -\sum_i y_i(\delta_{ik} - p_k). \] \[ \frac{\partial L}{\partial z_k} = -\sum_i y_i \delta_{ik} + p_k \sum_i y_i = -y_k + p_k(1) = \boxed{p_k - y_k}. \]

40. Reference implementation for stable loss and logits gradients

Implementation Pattern: Fused Softmax Cross Entropy
struct ExampleLossResult {
    float loss = 0.0F;
    std::vector<float> probabilities;
    std::vector<float> logits_gradient;
};

ExampleLossResult softmax_cross_entropy(const std::vector<float>& logits, std::size_t target) {
    if (logits.empty() || target >= logits.size()) {
        throw std::invalid_argument("Invalid logits or target");
    }
    const float maximum = *std::max_element(logits.begin(), logits.end());
    std::vector<float> probabilities(logits.size());
    float sum = 0.0F;
    for (std::size_t i = 0; i < logits.size(); ++i) {
        probabilities[i] = std::exp(logits[i] - maximum);
        sum += probabilities[i];
    }
    for (float& p : probabilities) p /= sum;

    const float log_sum_exp = maximum + std::log(sum);
    const float loss = log_sum_exp - logits[target];

    std::vector<float> gradient = probabilities;
    gradient[target] -= 1.0F; // Exactly p - y

    return { loss, std::move(probabilities), std::move(gradient) };
}

Part XI & XII — Backpropagation & Dense Layer Gradients

41. What backpropagation actually does

Backpropagation repeatedly applies the multivariate chain rule in reverse order to find the derivative of the loss with respect to every weight and bias in the network.

44. Start with the scalar equation

For output neuron \(o\): \(z_o = \sum_i W_{oi} a_i + b_o\). Let \(g_o = \frac{\partial L}{\partial z_o}\):

\[ \boxed{\frac{\partial L}{\partial W_{oi}} = g_o a_i}, \qquad \boxed{\frac{\partial L}{\partial b_o} = g_o}, \qquad \boxed{\frac{\partial L}{\partial a_i} = \sum_o g_o W_{oi}}. \]

45. Vector form of the dense backward pass

Mathematical Result: Matrix Backward Equations
\[ \boxed{\frac{\partial L}{\partial W} = \delta a^T}, \qquad \boxed{\frac{\partial L}{\partial \mathbf{b}} = \delta}, \qquad \boxed{\frac{\partial L}{\partial \mathbf{a}} = W^T \delta} \]

46. Why the weight gradient is an outer product

Given \(a = \begin{bmatrix} 2 \\ -1 \end{bmatrix}\) and upstream error \(\delta = \begin{bmatrix} 0.4 \\ -0.8 \end{bmatrix}\):

\[ \frac{\partial L}{\partial W} = \delta a^T = \begin{bmatrix} 0.4 \\ -0.8 \end{bmatrix} \begin{bmatrix} 2 & -1 \end{bmatrix} = \begin{bmatrix} 0.4(2) & 0.4(-1) \\ -0.8(2) & -0.8(-1) \end{bmatrix} = \begin{bmatrix} 0.8 & -0.4 \\ -1.6 & 0.8 \end{bmatrix}. \]

47. Reference dense backward implementation

Implementation Pattern: Dense Backward Pass
std::vector<float> backward_dense(
    const std::vector<float>& input,
    const std::vector<float>& weights,
    std::size_t input_size,
    std::size_t output_size,
    const std::vector<float>& upstream,
    std::vector<float>& grad_weights,
    std::vector<float>& grad_bias
) {
    std::vector<float> grad_input(input_size, 0.0F);
    for (std::size_t o = 0; o < output_size; ++o) {
        const float g = upstream[o];
        grad_bias[o] += g;
        const std::size_t row = o * input_size;
        for (std::size_t i = 0; i < input_size; ++i) {
            grad_weights[row + i] += g * input[i];
            grad_input[i] += weights[row + i] * g;
        }
    }
    return grad_input;
}

// One SGD update on one example; returns the loss.
float train_step(
    const neural::Tensor& input,
    std::size_t target,
    const neural::SGD& optimizer
) {
    const neural::Tensor logits = forward(input);
    const neural::LossResult result =
        neural::softmax_cross_entropy(logits, target);

    neural::Tensor gradient =
        layers_.back()->backward(result.logits_gradient);

    for (std::size_t i = layers_.size() - 1; i > 0; --i) {
        const std::size_t k = i - 1;
        gradient = relus_[k].backward(gradient);
        gradient = layers_[k]->backward(gradient);
    }

    for (auto& layer : layers_) {
        optimizer.step(*layer);
    }

    return result.loss;
}

Part XV & XVI — Weight initialisation & Training on MNIST

57. Why not start every weight at zero?

Starting with zero weights produces symmetric gradients across all hidden neurons. All neurons in a layer would compute the same value and update identically. Random initialisation breaks this symmetry.

58. He initialisation

Designed for ReLU networks:

\[ W_{ij} \sim \mathcal{N}\left(0, \frac{2}{n_{\text{in}}}\right), \qquad \sigma = \sqrt{\frac{2}{n_{\text{in}}}}. \]

59. Xavier initialisation

Designed for linear and sigmoid outputs:

\[ W_{ij} \sim U\left(-\sqrt{\frac{6}{n_{\text{in}} + n_{\text{out}}}}, \sqrt{\frac{6}{n_{\text{in}} + n_{\text{out}}}}\right). \]

  • train-images-idx3-ubyte: Magic 2051, 60000 images, 28 rows, 28 cols.
  • train-labels-idx1-ubyte: Magic 2049, 60000 labels (0–9).

Part XXIX — Batch Training and Batch Normalisation

89. From one example to a batch

The original training procedure processed one image at a time. For every image, the network performed a forward pass, calculated the loss, propagated gradients backwards, and updated its parameters. This is stochastic gradient descent (SGD) with a batch size of one.

Batch training processes several examples before updating the parameters. If a batch contains \(B\) examples, the network calculates predictions and losses for all \(B\) examples, accumulates their gradient contributions, and performs one optimiser update.

Mathematical Result: Mean Batch Loss
\[ \boxed{ L_{\mathrm{mean}} = \frac{1}{B}\sum_{i=1}^{B}L_i } \]

Here, \(L_i\) is the loss for example \(i\). The mean loss gives each example equal weight while keeping the loss scale independent of the number of examples in the batch.

The mean loss is differentiated with respect to the network's parameters. Its gradient is the average of the individual examples' gradients. Consequently, each example contributes \(1/B\) of its individual gradient to the batch gradient.

90. What Batch Normalisation does

Batch Normalisation (BatchNorm or BN) normalises activations separately for each feature across the examples in a mini-batch. It then applies learnable scale and shift parameters.

Consider an input tensor \(X\) of shape \((B,F)\), where \(B\) is the batch size and \(F\) is the number of features. For each feature \(j\), BatchNorm calculates statistics across the batch dimension.

BatchNorm is not simply a fixed operation that forces every layer's output to have zero mean and unit variance. Its learned parameters \(\gamma\) and \(\beta\) allow the network to choose an appropriate output scale and offset.

91. Calculating the batch mean

For a particular feature \(j\), let its activation in example \(i\) be \(x_{ij}\). The batch mean for that feature is

\[ \boxed{ \mu_j = \frac{1}{B}\sum_{i=1}^{B}x_{ij} } \]

The mean describes the average activation of the feature across the current batch. Every example contributes to the same feature mean.

92. Calculating the batch variance

Variance measures the spread of the activations around their mean. BatchNorm uses the population variance of the current batch:

\[ \boxed{ \sigma_j^2 = \frac{1}{B}\sum_{i=1}^{B}(x_{ij}-\mu_j)^2 } \]

The divisor is \(B\), rather than \(B-1\). This is the variance convention used in the standard training-time BatchNorm calculation.

93. Normalising the activations

The mean is subtracted from each activation, and the result is divided by the standard deviation:

\[ \boxed{ \hat{x}_{ij} = \frac{x_{ij}-\mu_j} {\sqrt{\sigma_j^2+\epsilon}} } \]

The small positive constant \(\epsilon\) improves numerical stability and prevents division by zero. Without it, a feature with zero variance would have a zero denominator.

Normalisation centres the batch activations and scales their spread. With nonzero variance, their normalised values have mean approximately zero and variance approximately one. The exact variance is slightly affected by \(\epsilon\).

94. The learnable scale and shift

BatchNorm transforms the normalised values using two trainable parameters for each feature:

\[ \boxed{y_{ij}=\gamma_j\hat{x}_{ij}+\beta_j} \]
  • \(\gamma_j\) is the learned scale.
  • \(\beta_j\) is the learned shift.

The usual initial values are \(\gamma_j=1\) and \(\beta_j=0\), so the initial transformation preserves the normalised values. Training can change both parameters.

BatchNorm therefore performs four main operations during its training forward pass: calculate the mean, calculate the variance, normalise the activations, and apply the learned scale and shift.

95. A numerical example

Suppose one feature has four activations: \(X=[2,4,6,8]\). Its mean is \(5\), and its population variance is \(5\). If \(\epsilon\) is ignored for this illustrative calculation, its normalised values are approximately:

\[ \hat{X} = [-1.342,-0.447,0.447,1.342] \]

If \(\gamma=1\) and \(\beta=0\), these are also the outputs. If \(\gamma=2\) and \(\beta=1\), the outputs become approximately \([-1.683,0.106,1.894,3.683]\).

The second example demonstrates that BatchNorm's final output is not required to retain zero mean and unit variance. The learned scale and shift can change both.

Part XXX — BatchNorm: Deriving the Backward Pass

96. What enters and leaves backward()

Backpropagation supplies each operation with the gradient of the loss with respect to that operation's output. The operation uses its local derivative to calculate the gradient with respect to its input.

For BatchNorm, define the incoming gradient for feature \(j\) and example \(i\) as

\[ g_{ij} = \frac{\partial L}{\partial y_{ij}} \]

BatchNorm must calculate the gradients of its learned parameters \(\gamma_j\) and \(\beta_j\), as well as the gradient with respect to each input activation \(x_{ij}\).

97. Deriving the shift gradient

Since \(y_{ij}=\gamma_j\hat{x}_{ij}+\beta_j\), differentiating with respect to the shift gives

\[ \frac{\partial y_{ij}}{\partial\beta_j}=1 \]

Applying the chain rule and summing the contributions from the batch:

\[ \boxed{ \frac{\partial L}{\partial\beta_j} =\sum_{i=1}^{B}g_{ij} } \]

Every example contributes its incoming gradient because changing \(\beta_j\) changes every output for that feature by the same amount.

98. Deriving the scale gradient

Differentiating the output with respect to the scale parameter gives

\[ \frac{\partial y_{ij}}{\partial\gamma_j}=\hat{x}_{ij} \]

Applying the chain rule:

\[ \boxed{ \frac{\partial L}{\partial\gamma_j} =\sum_{i=1}^{B}g_{ij}\hat{x}_{ij} } \]

Each contribution is weighted by the corresponding normalised activation. Positive and negative normalised values can therefore contribute differently to the scale gradient.

99. Why the input gradient is more complicated

A common mistake is to assume that the output for example \(i\) depends only on input \(x_i\). It also depends on the batch mean and variance, and those statistics depend on every input in the batch.

Changing \(x_i\) affects its own numerator, the batch mean, and the batch variance. The changed statistics can also affect the normalised outputs of other examples. Backpropagation must account for all these paths through the computation graph.

100. Start with the normalisation equation

For one feature, temporarily omit its feature index and write:

\[ \hat{x}_i = (x_i-\mu)(\sigma^2+\epsilon)^{-1/2} \]

Define the inverse standard deviation as

\[ r=(\sigma^2+\epsilon)^{-1/2} \]

Then \(\hat{x}_i=(x_i-\mu)r\). The output equation is \(y_i=\gamma\hat{x}_i+\beta\), so the gradient arriving at the normalised value is

\[ q_i=\frac{\partial L}{\partial\hat{x}_i} =\gamma g_i \]

101. The variance path

The inverse standard deviation depends on the variance. Its derivative is

\[ \frac{\partial r}{\partial\sigma^2} =-\frac{1}{2}(\sigma^2+\epsilon)^{-3/2} \]

Since every normalised value uses the same variance, the gradient with respect to the variance receives contributions from every example:

\[ \frac{\partial L}{\partial\sigma^2} =-\frac{1}{2}(\sigma^2+\epsilon)^{-3/2} \sum_{k=1}^{B}q_k(x_k-\mu) \]

This term represents the effect of changing the batch's spread on all normalised outputs.

102. The mean path

The batch mean also depends on every input:

\[ \frac{\partial\mu}{\partial x_i}=\frac{1}{B} \]

A change in one input shifts the mean, which affects every normalised activation. The derivative must therefore combine the direct path from \(x_i\), the mean path, and the variance path.

103. The complete input-gradient equation

Applying the chain rule to these paths and simplifying gives the standard BatchNorm input gradient. For one feature, with \(r=(\sigma^2+\epsilon)^{-1/2}\):

Mathematical Result: BatchNorm Input Gradient
\[ \boxed{ \frac{\partial L}{\partial x_i} =\frac{\gamma r}{B} \left[ Bg_i-\sum_{k=1}^{B}g_k -\hat{x}_i\sum_{k=1}^{B}g_k\hat{x}_k \right] } \]

All sums are over the examples in the batch for the same feature. The expression accounts for the direct input path and the indirect effects through the batch mean and variance.

104. Interpreting the three terms

  • \(Bg_i\): the direct contribution of the current example's incoming gradient.
  • \(-\sum_k g_k\): the correction caused by the shared batch mean.
  • \(-\hat{x}_i\sum_k g_k\hat{x}_k\): the correction caused by the shared batch variance.

The factor \(\gamma r/B\) scales the combined result. In particular, the division by \(B\) is part of the derivative of BatchNorm; it is not an instruction to average all gradients a second time.

105. Mapping the derivation to NeuralEngine

In the current implementation, the incoming gradient is output_gradient. For each feature, the implementation calculates two sums: 

sum_gradient += grad;
sum_gradient_normalized += grad * x_hat;

These correspond to \(\sum_k g_k\) and \(\sum_k g_k\hat{x}_k\). The input gradient is then calculated using the derived equation: 

input_gradient.at({i, j}) =
    (gamma_[j] * inverse_std_[j] / n)
    * (n * grad
       - sum_gradient
       - x_hat * sum_gradient_normalized);

Here, gamma_[j] is \(\gamma\), inverse_std_[j] is \(r\), and n is the batch size \(B\). The formula should retain its division by n.

106. The backward chain through Dense, BatchNorm and ReLU

Consider the forward sequence:

\[ z = \operatorname{Dense}(x),\qquad a = \operatorname{BatchNorm}(z),\qquad h = \operatorname{ReLU}(a) \]

Backpropagation traverses these operations in reverse order: 

gradient = relu4.backward(gradient);
gradient = bn4.backward(gradient);
gradient = fc4.backward(gradient);

ReLU receives the gradient with respect to its output and returns the gradient with respect to its input. BatchNorm receives that result as the gradient with respect to its output and returns the gradient with respect to its input. Dense then receives the gradient with respect to its output.

The variable name gradient remains the same, but its mathematical meaning changes after every call. Each operation returns the gradient required by the preceding operation.

107. Batch size one

If \(B=1\), the only activation equals its own batch mean, so \(\mu=x_1\) and \(\sigma^2=0\). Therefore:

\[ \hat{x}_1=\frac{x_1-x_1}{\sqrt{\epsilon}}=0 \]

The output becomes \(y_1=\beta\), independent of the input. Substituting \(B=1\) into the input-gradient equation also gives zero. Thus, training BatchNorm with a batch size of one blocks the gradient to the preceding layer through that BatchNorm operation.

Part XXXI — Gradient Scaling and Mean Batch Loss

108. Why the loss and gradient must agree

For softmax cross-entropy, the gradient of the loss for one example with respect to a logit \(z_j\) is \(p_j-y_j\), where \(p_j\) is the predicted probability and \(y_j\) is the one-hot target.

\[ \frac{\partial L_i}{\partial z_{ij}}=p_{ij}-y_{ij} \]

For the mean loss across a batch, the derivative is instead:

\[ \boxed{ \frac{\partial L_{\mathrm{mean}}}{\partial z_{ij}} =\frac{p_{ij}-y_{ij}}{B} } \]

Returning the mean scalar loss while returning unscaled gradients would make the loss value and its gradient represent different objectives: the mean loss and the sum of individual losses, respectively.

109. Where the averaging occurs

NeuralEngine now scales the batch logits gradient by \(1/B\) in softmax_cross_entropy(). This means that the gradient entering backpropagation already corresponds to the mean batch loss.

Dense accumulates the weight and bias gradient contributions across the batch. Since the incoming gradients already contain the factor \(1/B\), Dense must not divide its accumulated parameter gradients by \(B\) again.

BatchNorm similarly accumulates the contributions to \(\gamma\) and \(\beta\). It must not perform a separate division by \(B\) when its incoming gradients have already been scaled at the loss.

Implementation Rule
  • Scale the batch loss gradient once, at the loss function.
  • Accumulate Dense weight and bias gradients without another division.
  • Accumulate BatchNorm scale and shift gradients without another division.
  • Keep BatchNorm's input-gradient formula, including its internal \(1/B\).
  • Do not insert arbitrary gradient averaging into ReLU or other operations.

This rule applies to the batch loss overload. The single-example loss has \(B=1\), so its gradient requires no additional scaling.

110. Why the BatchNorm input gradient is not averaged again

The input-gradient equation already derives how the incoming gradients propagate through the normalisation operation. Its factor \(1/B\) comes from differentiating the batch statistics.

If the incoming gradient has already been scaled by \(1/B\), the BatchNorm input gradient automatically carries that scaling through the formula. Dividing the returned input gradient by \(B\) again would introduce an unwanted additional factor.

Gradient scaling must therefore be distinguished from derivative factors that naturally arise when differentiating an operation. Not every occurrence of \(1/B\) in a derivative is an additional loss-averaging step.

111. Batch gradients versus parameter updates

A batch produces one set of parameter gradients and normally one optimiser update. With per-example SGD, parameters are updated after each example. With batch training, parameters remain fixed while the examples in a batch are processed, and the optimiser updates them after backpropagation.

The number of updates per epoch consequently changes with batch size. Equal epoch counts do not imply equal numbers of parameter updates or identical optimisation trajectories.

Part XXXII — Training Stability, Learning Rates and BatchNorm

112. Learning rate and overshooting

Gradient descent updates parameters according to

\[ \theta_{\mathrm{new}} =\theta_{\mathrm{old}}-\eta\nabla_\theta L \]

The learning rate \(\eta\) controls the step size. If the learning rate is too high for the local geometry of the loss surface, updates can overshoot regions of low loss. Repeated overshooting can produce oscillation, unstable loss values, or divergence.

If calculations overflow or invalid numerical values propagate through the network, the loss can become non-finite, including positive infinity (\(\mathrm{Inf}\)).

113. How BatchNorm can affect optimisation

As the weights of a preceding layer change, the scale and offset of its activations can change. BatchNorm uses current batch statistics during training to normalise those activations before applying its learned scale and shift.

This can make the network less sensitive to some changes in activation scale and can improve the conditioning of the optimisation problem. In some settings, it allows the use of a higher learning rate and improves training speed or stability.

BatchNorm does not directly cap the loss, clip gradients, or guarantee convergence. The learned scale can change, and other parts of the network can still become unstable. Whether BatchNorm helps depends on the architecture, batch size, learning rate, and training procedure.

114. Accuracy and cross-entropy measure different things

Accuracy measures the fraction of examples whose predicted class is correct. Cross-entropy also penalises how much probability the model assigns to the correct class.

A model can achieve higher accuracy while having higher mean cross-entropy. For example, it may classify more examples correctly but assign less probability to the correct class on those examples, or make a few highly confident mistakes.

A higher cross-entropy value alone does not prove that a model has become less confident overall. Confidence and calibration should be assessed using the actual predicted probabilities, alongside accuracy and loss.
